# BS_HFN 毕业答辩可能问题与参考答案

适用项目：**基于 Web 技术与 FFmpeg 的学生课后辅导系统**
整理日期：2026-09-27

> 使用建议：不要逐字背诵。先说结论，再结合页面、数据库表或业务流程举例，单个问题尽量控制在 30～60 秒。老师继续追问时，再补充“技术细节”部分。

---

## 一、选题与总体设计

### 1. 为什么选择“学生课后辅导系统”作为毕业设计？

**参考答案：**

我选择这个题目，是因为传统课程平台经常只解决“上传资料”或“观看视频”中的单一问题，课程、班级、作业、测验、答疑和学习反馈之间比较割裂。我的项目希望围绕课后学习形成完整闭环：教师建立课程和班级，学生申请加入班级，教师审批后开放班级任务；学生观看视频、记录进度、提交作业和测验；教师再进行答疑、批改和数据分析。

这个题目也能综合体现 Web 开发、数据库设计、权限控制、文件管理、视频转码、异步任务和前端交互，比较适合作为完整的软件工程类毕业设计。

**关键词：** 教学闭环、真实业务流程、多角色协作、综合实践。

### 2. 这个系统最主要的特色或创新点是什么？

**参考答案：**

我认为主要有四点：

1. 课程与教学班分离。加入课程不代表自动加入班级，学生必须提交入班申请，由教师审批后才能看到班级绑定的作业和测验。
2. 视频不是简单上传后直接播放，而是使用 FFmpeg 和 ffprobe 完成探测、转码、HLS 切片和封面生成，并提供失败重试、超时恢复和管理员监管。
3. 学习进度支持断网缓存和恢复补传，服务端通过请求编号去重，避免“服务端成功但客户端丢失响应”造成观看时长重复累计。
4. 测验同时支持在线试题和附件试卷。在线试题由系统自动评分，附件试卷可以直接发布给学生，再由教师人工批改。

这些功能不是孤立页面，而是与权限、通知、统计、审计和数据库事务结合在一起。

### 3. 你在这个项目中主要完成了哪些工作？

**参考答案：**

我完成了从需求分析、数据库设计、接口设计到前端页面和测试验收的完整过程。后端包括认证权限、课程班级、学习记录、作业测验、通知、统计、管理员后台和视频处理；前端包括学生、教师、管理员三类工作区及移动端适配；数据库目前有 26 张业务表，并通过 Alembic 管理版本。

此外，我还准备了项目内 FFmpeg、Windows 启动脚本、部署环境检测脚本、换电脑迁移文档、演示数据、数据库备份以及自动化测试。答辩时展示的主要业务数据也经过专门设计，不依赖临时手工创建。

### 4. 系统采用了什么总体架构？

**参考答案：**

系统采用前后端分离的 B/S 架构。前端使用 Vue 3、Vite、Vue Router、Pinia、Axios 和 Element Plus；统计图表使用 ECharts，HLS 视频播放使用 hls.js。后端使用 Flask Application Factory 和 Blueprint 组织接口，Service 层处理业务逻辑，Flask-SQLAlchemy 访问 MySQL，Flask-Migrate 管理数据库迁移。

Redis用于令牌撤销记录和 Celery 消息队列，Celery负责异步视频处理；FFmpeg与ffprobe负责媒体探测、转码、HLS切片和封面生成。前端只通过 REST API 与后端交互，不直接访问数据库。

### 5. 为什么采用前后端分离，而不是直接使用后端模板渲染？

**参考答案：**

这个系统包含较多状态复杂的交互，例如测验自动保存、视频学习进度、弹窗内部编辑、分页筛选、消息未读数量和角色导航。使用 Vue 可以把这些状态拆分为组件和响应式数据，交互体验更稳定，也便于复用课程卡片、统计图表、附件预览和长文本组件。

前后端分离后，权限和数据规则统一放在后端接口，前端只负责展示与交互。将来如果增加移动端或小程序，也可以继续使用现有接口。不过它的代价是要额外处理跨域、令牌刷新、接口错误和前后端状态同步。

## 二、数据库与核心业务流程

### 6. 数据库为什么有 26 张业务表？是不是设计得过多？

**参考答案：**

26 张表是随着完整业务闭环拆分出来的，不是为了追求数量。核心实体包括用户、分类、课程、课程学生关系、章节、视频、学习记录、笔记、答疑、作业、测验、公告和收藏；后续为了真实教学流程增加了教学班、班级成员、班级课程、入班申请、密码重置申请、站内通知、审计日志以及学习进度去重凭据等表。

如果把这些状态全部放到少数大表，会产生大量空字段、重复数据和难以维护的多值字段。现在通过主外键、唯一约束和关系表表达多对多关系，结构更清晰。数据库另有一张 `alembic_version` 表用于迁移版本管理，但它不计入 26 张业务表。

### 7. 为什么视频和附件不直接存进 MySQL？

**参考答案：**

数据库只保存文件相对路径和媒体元信息，实际文件保存在 `backend/media`。视频、图片和压缩包通常体积较大，如果作为 BLOB 写入 MySQL，会增加数据库备份、恢复和查询压力，也不利于 HLS 分片和静态资源读取。

当前方案让 MySQL 管理结构化业务数据，文件系统管理媒体内容。为了避免两者不一致，上传、替换和删除时会校验路径必须位于媒体根目录内，并在数据库操作成功后按业务规则清理旧文件。迁移电脑时也明确要求同时复制数据库备份和完整媒体目录。

### 8. “课程”和“班级”有什么区别？为什么要分开设计？

**参考答案：**

课程是可学习的教学资源集合，包含章节、视频、作业和测验；班级是教师管理学生名册和实际授课关系的组织单位。同一门课程可以关联多个班级，一个班级也可以关联多门课程，因此两者通过 `teaching_class_course` 建立多对多关系。

分开后，教师可以维护一套课程内容，再把它用于不同班级。学生自主加入课程后可以浏览公共课程内容，但只有班级申请被教师批准，才获得该班级绑定任务的访问权限。这样既支持开放选课，也保留实际教学班管理。

### 9. 学生申请加入班级的完整流程是什么？

**参考答案：**

学生先进入课程详情并加入课程，然后查看该课程关联的教学班，选择班级提交申请。申请写入 `teaching_class_join_request`，初始状态为 `PENDING`，此时不会创建正式班级成员关系，也不能看到班级绑定的作业和测验。

教师在班级管理的“入班审批”中同意或拒绝。只有审批成功，系统才创建 `teaching_class_student` 关系，并同步班级关联课程。学生和教师都会收到站内通知。学生还可以在“我的班级”查看申请记录，并在教师处理前撤回申请。

### 10. 如何保证学生未经审批看不到班级作业和测验？

**参考答案：**

这项限制不是只在前端隐藏按钮，而是在后端统一校验。对于已经关联教学班的课程，学生除了要有有效的课程关系，还必须存在对应教学班的正式成员关系；待审批申请本身不算成员。

作业列表、测验列表、详情读取、附件下载和提交接口都复用相同的任务访问条件，直接猜测任务编号也会返回无权访问。发布通知的收件人查询也使用同样条件，避免学生虽然看不到任务，却提前从通知中获得任务标题。

### 11. 课程为什么设计草稿、已发布、已下线三种状态？

**参考答案：**

课程使用状态机管理生命周期。草稿用于教师准备内容，学生不可见；发布后学生可以浏览和学习；下线后停止新的公开学习，但保留历史关系和学习记录，教师仍可维护内容并重新发布。

我没有把“下线”直接做成删除，因为课程可能已经关联学生、班级、进度、作业和成绩。直接删除会破坏历史数据。对于视频替换或删除等可能影响学习记录的操作，也要求课程处于草稿或下线状态，并在界面中明确提示影响。

### 12. 不限时作业是如何实现的？

**参考答案：**

作业的截止时间字段允许为空。教师创建作业时明确选择“不限时”或“指定截止时间”：不限时向后端发送 `deadline: null`，页面显示“长期有效”；指定截止时间时，日期才是必填项。

不限时不代表永远不能停止，教师仍可以主动关闭作业。这样避免了过去空时间被错误替换为当前时间、导致作业刚创建就截止的问题，同时保留教师控制提交入口的能力。

### 13. 在线试题和附件试卷有什么区别？

**参考答案：**

在线试题模式由教师在系统中添加单选题和判断题，发布前校验题目总分是否与测验总分一致。学生作答时答案自动保存，正式交卷后由系统根据标准答案自动评分。

附件试卷模式允许教师直接上传完整试卷，不需要再录入系统题目。学生查看试卷后提交文字或答卷附件，教师在提交记录中人工评分和填写评语。两种模式在接口和界面上明确分开，在线试题不会出现完整试卷上传入口。

### 14. 测验答案自动保存、超时交卷是怎样实现的？

**参考答案：**

学生开始测验后会生成测验记录，作答变化通过保存接口持续写入草稿。保存请求期间如果学生继续修改，前端会在当前请求结束后继续补存最新答案，避免慢请求覆盖后续输入。

达到截止时间或教师提前关闭测验时，系统按已保存草稿完成交卷：在线题自动评分，附件试卷进入待教师批改状态。为了诚实说明系统边界，当前本地答辩版没有常驻定时调度器；如果用户完全关闭页面，过期记录会在下一次相关查询时进行惰性结算。

### 15. 为什么学生提交后有时还能修改，有时不能修改？

**参考答案：**

作业在教师尚未批改、作业未关闭且未超过指定截止时间时，可以按照业务规则重新提交。教师完成批改后，成绩和评语已经形成正式教学结果，因此提交会被锁定，学生不能再修改正文或附件。

测验正式交卷后只能提交一次，也不能修改答案。这个限制同时在前端按钮状态和后端服务层执行，不能只依赖页面禁用。教师关闭任务后，学生也不能再开始新的提交。

## 三、视频、进度与异步任务

### 16. 视频上传后经历哪些处理步骤？

**参考答案：**

教师上传视频后，系统先保存原文件，再通过 ffprobe 获取时长、分辨率、编码和帧率等信息，然后使用 FFmpeg 转码为适合浏览器播放的 H.264/AAC 文件，生成 HLS 播放列表和分片，并截取视频封面。

数据库记录处理状态和步骤，主要阶段包括 `PROBING`、`TRANSCODING`、`HLS`、`COVER` 和 `FINISHED`。完成后状态为 `READY`，失败则保存失败阶段和可读错误信息，管理员可以判断是否满足重新转码条件。

### 17. 为什么使用 HLS，而不是直接播放原始 MP4？

**参考答案：**

原始视频的编码格式不一定被所有浏览器支持，而且大文件直接播放不利于分段加载。HLS 将视频拆成播放列表和多个小分片，浏览器可以按需请求，拖动和网络恢复更方便。

前端使用 hls.js 在 Chromium 等浏览器中播放 HLS；如果浏览器原生支持 HLS，也可以使用原生能力。当前项目实现的是单码率 HLS，没有声称已经支持多码率自适应，这是后续可以扩展的方向。

### 18. Redis 和 Celery 在系统中分别起什么作用？

**参考答案：**

Celery负责执行耗时的视频处理任务，使上传接口不必一直等待 FFmpeg 完成；Redis作为 Celery 的消息代理和结果后端。项目同时支持同步和异步两种视频处理模式，本地调试可以同步处理，答辩电脑启用异步模式时由独立 Celery 终端消费任务。

Redis在本项目中不仅服务于Celery，还保存JWT撤销记录。即使关闭异步视频处理，Redis仍然是认证流程的必要依赖。Redis不可用时，系统按安全策略拒绝令牌校验，而不是默认放行。

### 19. 视频转码失败后系统如何处理？

**参考答案：**

系统会记录视频当前状态、处理阶段、错误信息、最后更新时间以及原始文件是否存在。管理员的视频处理中心可以筛选等待、处理中、可播放和失败任务，并查看完整文件信息和错误原因。

原始文件存在且任务状态允许恢复时，可以重新转码；等待或处理中长时间没有更新的任务也可人工恢复。如果原始文件已经丢失，则不能伪装成可重试，只能清理失败记录。所有文件清理都限制在媒体根目录内，避免路径错误删除项目外文件。

### 20. 学习进度是怎样计算和保存的？

**参考答案：**

前端播放视频时按周期上报本次有效观看增量和播放位置，后端根据视频真实时长限制参数范围和单次增量，不能由前端直接提交任意完成百分比。累计进度由有效观看记录计算，达到设定阈值后标记为完成。

系统还保存最后播放位置，学生再次进入课程时可以继续学习。退出课程只停用课程关系，不删除已有进度、笔记和答疑，避免一次误操作造成历史学习数据丢失。

### 21. 网络断开时学习进度为什么不会丢失或重复累计？

**参考答案：**

网络失败时，前端会把进度记录按当前用户保存到浏览器本地队列，恢复联网或重新进入课程后补传。每条记录在发送前生成并持久保存唯一请求编号，重试继续使用原编号。

服务端通过 `learning_progress_receipt` 表保存已经处理的请求编号，并与学习增量放在同一个事务中。同一学生用相同编号重试相同内容时返回首次结果，不重复累计；相同编号携带不同内容则返回冲突。支持 Web Locks 的浏览器还会协调多个标签页的本地队列操作，但清理浏览器站点数据后，本地未补传记录仍会丢失，这是客户端缓存的客观边界。

## 四、认证、安全与一致性

### 22. 系统如何实现登录和身份认证？

**参考答案：**

系统使用 JWT，登录成功后返回 Access Token 和 Refresh Token。Access Token 用于普通接口访问，过期后前端通过 Refresh Token 进行一次并发受控的刷新，再重放原请求，避免多个接口同时失败时重复刷新。

刷新令牌采用轮换机制，退出登录后令牌标识写入 Redis 撤销集合。令牌中还带有与当前密码哈希相关的凭据签名，因此管理员重置密码或教师批准学生密码重置后，旧会话会失效，需要重新登录。

### 23. 学生找回密码为什么需要教师审批？具体流程是什么？

**参考答案：**

学生在登录页输入账号和已登记身份信息，提交希望使用的新密码。系统不会立即修改密码，而是生成有效期有限的密码重置申请，并通知当前班级教师。

教师在班级管理中只能审批自己班级学生的申请。同意后才写入新密码哈希，并使旧登录会话失效；拒绝、取消或过期都不会修改密码。管理员也可以核验身份后代重置师生密码，管理员重置会取消旧的待审批申请，避免迟到审批覆盖更新后的密码。

### 24. 如何防止学生、教师或管理员越权操作？

**参考答案：**

系统采用“角色权限加资源归属”的双重校验。JWT中的角色只解决“谁可以进入哪类接口”，具体操作还要检查资源所有权，例如教师只能编辑自己的课程、班级、作业和测验，也只能审批自己班级的学生。

学生端则检查课程成员、班级成员、任务可见性和提交记录所有者。管理员接口与普通业务接口分开，关键管理操作写入审计日志。前端隐藏无权限入口只是改善体验，真正的安全边界始终在后端。

### 25. 上传文件时做了哪些安全处理？

**参考答案：**

不同业务分别限制允许的扩展名、文件签名、大小和用途。例如课程封面限制为图片并设置大小上限，作业和测验附件使用白名单格式，视频会经过 ffprobe 验证，不能只通过修改扩展名绕过。

保存文件时使用随机文件名，不直接使用用户上传的原名称作为路径；数据库只保存受控相对路径。下载和预览附件必须经过登录、任务可见性和资源归属校验。PDF、图片和文本可以在线预览，其他格式降级为下载，项目没有夸大为完整 Office 在线编辑。

### 26. 如何处理重复提交、并发审批和数据竞争？

**参考答案：**

数据库层使用唯一约束防止重复课程关系、班级成员、收藏和重复申请等数据；服务层把可能冲突的操作放入事务，并在需要时使用行锁或条件更新。

例如入班审批、申请撤回和密码审批只有处于预期状态时才能更新，两个请求竞争时只有一个成功；测验正式提交只能完成一次；学习进度通过请求回执实现幂等。发生冲突时接口返回明确的 409，前端重新读取最新状态，而不是用旧响应覆盖页面。

### 27. 系统为什么统一使用 UTC 时间？

**参考答案：**

数据库连接会话按 UTC 写入，接口返回带 `Z` 的 ISO 8601 时间，前端再按照用户本地时区显示。这样可以避免后端、数据库和浏览器位于不同时区时出现截止时间偏移。

作业截止、测验开始结束、申请过期和通知时间都使用同一套时间规则。当前答辩电脑位于东八区，但数据层不直接依赖系统显示时区，换电脑后也更容易保持一致。

## 五、前端、统计、测试与交付

### 28. 前端界面和数据可视化是怎样设计的？

**参考答案：**

界面定位为高校教学门户风格，使用克制的蓝灰色、轻边框和有限阴影，避免过度装饰。表单控件、按钮和卡片有统一尺寸；弹窗固定在视口中央，长内容只在弹窗正文内滚动；班级列表采用固定高度的主从布局，分页区不随当前页数据量上下跳动。

统计图表使用 ECharts 6 按需加载和 SVG 渲染。学生查看学习进度和得分率，教师查看课程表现和发布状态，管理员查看角色和视频状态分布。图表直接使用后端聚合接口，并保留数值卡片、表格、空状态和完整名称入口，不生成虚构趋势或所谓“AI分析”。

### 29. 你如何证明项目功能是可靠的？

**参考答案：**

项目不是只做人工点击测试。后端使用 pytest 覆盖权限、业务边界、附件、事务、班级任务可见性和真实 FFmpeg 等场景；前端使用 Playwright 在隔离端口、内存 SQLite 和独立媒体目录中执行跨角色浏览器测试，不污染真实演示数据库。

最后一次交付验收中，后端 84 项通过、2 项环境可选测试跳过，Chromium 浏览器测试 137/137 通过；前端生产构建通过。真实 MySQL 演示数据又单独完成 63 项接口读取和 13 个真实页面检查，页面错误为 0。测试还覆盖 390px 移动端、断网补传、慢请求、重复操作、视频上传转码和 HLS 实际播放。

### 30. 项目如何部署？目前还有哪些不足和后续计划？

**参考答案：**

当前目标是 Windows 本地毕业答辩，不是公网生产部署。换电脑时需要重建 Python 虚拟环境和前端依赖，安装 MySQL 与 Redis，恢复最新 SQL，复制完整 `backend/media`、`backend/.env` 和项目内 `tools/ffmpeg`。项目提供 ANSI 编码的启动脚本和部署检测脚本，可以检查 Python、Node、依赖、FFmpeg、MySQL、Redis、Celery、数据库迁移、演示数据和前端构建。

目前的不足主要有：媒体由 Flask 开发模式提供，没有配置 Nginx 和生产级缓存；Refresh Token 仍保存在 `localStorage`，公网部署更适合使用 HttpOnly Cookie；HLS 只有单码率；完全关闭页面后的测验超时依赖后续查询结算；本地离线队列会随着浏览器站点数据清理而丢失；没有做公网压力测试和高可用部署。

后续可以增加 Nginx、HTTPS、对象存储、多码率自适应 HLS、独立定时任务、生产级日志监控、HttpOnly Cookie、数据库主从备份和更完整的无障碍测试。答辩时我会明确区分“已经实现的本地答辩功能”和“未来可以扩展的生产能力”。

## 答辩表达注意事项

1. 不要说“系统完全没有问题”，应说“主要业务闭环已经通过自动化与真实环境验收”。
2. 不要说“已经部署到互联网”，当前是 Windows 本地答辩部署。
3. 不要说“实现了智能推荐或AI分析”，当前统计是数据库实时聚合和 ECharts 展示。
4. 不要说“支持所有附件在线编辑”，当前是图片、PDF、文本预览，其他格式下载。
5. 不要说“视频支持自适应多码率”，当前实现的是 HLS 分片与浏览器播放。
6. 回答业务问题时，优先使用“学生申请—教师审批—权限开放—通知反馈”这样的完整流程表达。
7. 回答技术问题时，优先说明“前端体验”和“后端强制校验”是两层保障，不能只依赖页面按钮。
8. 如果老师问到未实现内容，先说明当前边界，再给出具体扩展方案，不要临时虚构已经完成的功能。
